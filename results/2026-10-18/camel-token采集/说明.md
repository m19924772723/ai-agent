# CAMEL token 采集（U22 收口补漏）

> 五要素：做了什么 / 为什么 / 怎么验证的 / 关键输出 / 复现步骤

## 做了什么

给 CAMEL 电子书 demo 补 token 统计：写 `StatsModel` 统计包装器（继承 BaseModelBackend，包装 inner.run 累计 usage），重跑拿到真实 token 数，三框架对比表补上成本列。

## 为什么

U20 跑 CAMEL 时没挂计数器，三框架对比表缺 CAMEL 的 token 成本（AgentScope 11926 有、AutoGen 未采集、CAMEL 空）。U22 收口补漏。

## 怎么验证的

- 实测重跑：5 轮 / 36.3 s / **11 次调用 / prompt 10309 + completion 6413 = 16722 tokens**（StatsModel 累计，非估算）
- 首次运行遇 `ValueError: No messages to process`（模型多消息返回边界），重跑即恢复——记录为多智能体随机性数据点
- 数字来源：包装器在每次 run() 后读 `response.usage` 累计

## 关键输出

- CAMEL 单本书成本：**16722 tokens / 11 次调用 / 36.3 s**
- 三框架成本列：AgentScope 11926（10 调用/51.6s）｜AutoGen 未采集（8 消息/46.7s）｜CAMEL 16722（11 调用/36.3s）
- 包装器踩坑 4 个（抽象方法/递归/初始化顺序）已修好并留在脚本注释里
