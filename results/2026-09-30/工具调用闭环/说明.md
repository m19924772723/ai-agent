# 成果 2026-09-30：工具调用闭环（U3 单元）

> 五要素：做了什么 / 为什么 / 怎么验证的 / 关键输出 / 复现步骤

## 做了什么

把母本 `code/chapter1/FirstAgentTest.py`（提示词 + 正则解析、依赖 wttr.in 与 Tavily）改造成**零外部依赖**的实验，并对比两种工具调用契约实现：

1. **三个自写工具**：`get_current_time`（本机时间）、`hours_until`（到指定时刻的小时数）、`calculate`（`ast` 白名单安全求值）。
2. **两条路线各跑一遍**：`mode=native`（OpenAI 原生 function calling，tools schema）与 `mode=prompt`（母本风格：提示词约定 `Thought/Action` + 自写正则解析）。
3. 任务故意设计成**依赖链**（先拿时间 → 再算间隔 → 再乘 7），保证出现真正的多轮调用而非一轮猜完。
4. 逐轮把 `tool_calls` 原始 JSON 落盘：`labs/ch01-toolcall/out/run.json`。

## 为什么

`plan.md` 单元 U3 的验收要求：① 模型连续 ≥2 轮调用自写工具并给出最终答案；② 留下 tool_call 原始 JSON；③ 无外部付费 API 依赖。而且「工具调用契约靠什么保证」是第 1 章最该量化的一点——教程给的写法（提示词 + 正则）在工程上是有风险的。

## 怎么验证的

| 项 | 证据 |
|---|---|
| 多轮闭环 | 3 次工具调用按依赖顺序发生：`get_current_time → hours_until(target="2026-10-07 00:00") → calculate("156.85 * 7")`，参数里带着上一步返回值 |
| 答案正确 | 两条路线给出同一结果：现在 2026-09-30 11:09、间隔 156.85 小时、×7 = 1097.95 |
| 无外部依赖 | 三个工具全部本地计算（时间取系统时钟、算术走 `ast` 白名单），零 API key、零网络请求 |
| 原始数据可查 | `out/run.json` 记录两模式的逐轮内容、tool_call 原始 JSON、token、耗时 |
| 环境干净 | 独立 venv（D 盘解释器），未污染系统 Python；密钥从环境变量取，未写入文件 |

## 关键输出（2026-09-30 实测，step-3.7-flash）

| 路线 | 轮数 | 工具调用 | token | 耗时 | 解析失败 |
|---|---|---|---|---|---|
| 原生 function calling | 4 | 3 | **2489** | **8.16 s** | 0 |
| 母本风格（提示词 + 正则） | 4 | 3 | 3051 | 11.29 s | 0 |

**三条结论**
1. 原生路线 **省 18% token、快 28%**，且调用是结构化 JSON（`id / type / function.name / arguments`），可程序化校验；提示词路线靠正则，正确性依赖"模型每次写引号"。
2. 三次调用烧掉约 2500 token——**多轮 Agent 的成本要按"轮数 × 上下文长度"估**，因为每轮都重发历史（含工具返回）。
3. 工具设计原则：**确定性计算外置**（`ast` 白名单求值），模型只负责决定算哪个式子。
