# 成果 2026-10-02：手写 ReAct 循环（U5 单元）

> 五要素：做了什么 / 为什么 / 怎么验证的 / 关键输出 / 复现步骤

## 做了什么

不抄母本示例，自己重写出最小 ReAct 循环（`Thought → Action → Observation`，`max_steps=4`），并加了一个**对照组**回答"ReAct 比一次提示词强在哪"：

- 任务：现在到 2026-10-07 00:00 还有多少小时？换算成天（保留 1 位小数）——需要模型不可能知道的实时事实，逼出"必须调工具"的差别。
- 路线 A：ReAct + 两个本地工具（`now()` / `calculate()`，`ast` 白名单求值）。
- 路线 B：一次提示词直接要 JSON 答案，不给任何工具。
- 迭代过程全部留档：v1（参数解析 bug，失败）、v2（正则跨行 bug，勉强成功）、v3（修好，4 步干净收尾）。

## 为什么

`plan.md` 单元 U5 的验收：① 日志能看到 ≥2 轮思考/行动/观察；② 能讲清它与"一次提示词输出 JSON"的区别。第 4 章 4.2.4 专门讲"局限性与调试技巧"，本实验把"调试"这一半做实。

## 怎么验证的

| 项 | 证据 |
|---|---|
| 多轮闭环 | 3 次工具调用按依赖顺序：`now()` → `calculate(小时数)` → `calculate(天数)` |
| 答案正确 | 手工核对 10-02 10:29:03 → 10-07 00:00 = 13h30m57s + 4×24h = **109.52 h = 4.56 天**，与模型答案一致 |
| 对照组真的错 | 路线 B 输出 17472 小时 / 728 天（差两个数量级），证明"没工具只能猜" |
| 失败可追溯 | v1/v2/v3 三份 JSON 在 `labs/ch04-react-min/out/`，每次的原始输出都在里面 |
| 环境干净 | 独立 venv（D 盘解释器），密钥从环境变量取 |

## 关键输出（2026-10-02 实测，step-3.7-flash）

| 版本 | 现象 | 根因 | 结果 | token |
|---|---|---|---|---|
| v1 | 连续 3 步报「表达式含不允许的字符」→ 无答案 | 解析层不支持 `name="值"`，把 `expression="…"` 整串当表达式 | 失败 | 4688 |
| v2 | 第 3 步解析失败，第 4 步自纠错答对 | `Action:` 正则跨行捕获，把模型**自造的 `Observation:`** 也吃进来 | 成功但浪费一步 | 4244 |
| **v3** | 4 步干净收尾，答案正确 | 支持 `name=值` + `Action` 只取首行 + 丢弃模型伪造的 Observation | **成功** | **3181** |

| 路线 | 工具调用 | token | 耗时 | 答案 |
|---|---|---|---|---|
| A：ReAct | 3 | 3181 | 25.82 s | 约 109.5 小时 / 4.6 天 ✅ |
| B：一次提示词 | 0 | **687** | 6.63 s | 17472 小时 / 728 天 ❌ |

**四条结论**
1. ReAct 的失败大多在**协议解析层**，不在模型层（三次跑模型逻辑都对）。
2. 模型会**自导自演 Observation**——"观察"这一栏只认自己执行工具的结果。
3. 便宜但错更贵：对照路线 1/5 成本换来两个数量级错误，这正对应 U2 判断清单里"需要外部事实 → 该上 Agent"。
4. 协议写稳比换模型便宜：v1 → v3 **省 47% token**，模型一个没换。
