# results/ —— 每日成果归档

> 这里放**当天完成并验证过的成品**，和 `notes/` 分工：notes = 过程（读了什么、怎么想的），results = 成品（能给别人看的交付物）。

## 1. 什么算「成果」（全部满足才归档）

| 判定 | 说明 |
|---|---|
| ✅ 完成 | 不是计划、不是草稿、不是 AI 生成待审的文案 |
| ✅ 验证过 | 有真实输出：跑通的脚本/评测数字/核对过的文档，不是「运行成功」四个字 |
| ✅ 可复现 | 别人（或两周后的我）照着记录能重新跑出来 |
| ✅ 有落点 | 能指出它服务哪个项目/哪个面试问题 |

## 2. 目录规则

```
results/
├── README.md                 # 本文件：规则 + 成果台账（新成果在台账加一行）
└── YYYY-MM-DD/
    └── <成果名>/
        ├── 说明.md           # 五要素：做了什么 / 为什么 / 怎么验证的 / 关键输出（数字/片段）/ 复现步骤
        └── （必要的产物文件，体积小的直接放；大文件只写路径）
```

- 目录按**成果完成日期**分（和 `notes/YYYY-MM-DD.md` 同名好对应）；
- 一个成果一个目录；同一天多个成果并列；
- 大体积产物（模型、数据集、日志）不进来，写绝对路径引用即可（`.gitignore` 已排除常见大文件）；
- 每个成果在当天 `notes/YYYY-MM-DD.md` 的「用进哪个项目」里写一句链接到 `results/` 对应目录。

## 4. 归档动作（每天收尾 5 分钟）

1. 今天有没有满足第 1 节四条的东西？有 → 建 `results/YYYY-MM-DD/<成果名>/`，写说明；
2. 台账加一行（最新在上）；3. `notes/` 当天笔记里链过去；4. git 提交（本地）。

> 反例（这些**不**进 results）：读了第 X 章（那是 progress.md 的事）、踩坑记录（留在 notes）、计划与任务单（留在 `plan.md`）。
