# AutoGen 软件开发团队 demo（U19）

## 做了什么

把第 6 章 AutoGen 的「软件开发团队」多智能体 demo（`autogen_software_team.py`，四角色：PM/工程师/代码审查员/用户代理）适配到已注入密钥的 OpenAI 兼容端点（deepseek-flash），在 `labs/ch06-autogen/` 跑通一个协作任务：团队写 `distance(p1,p2)` 欧氏距离函数。**任务文本避开终止词 + UserProxy 注入 input_func + model_info 显式声明**（AutoGen 0.7 三个必改点）。

## 为什么（学习目的）

阶段2 对照物：AutoGen 是继 AgentScope（U18）后的第二个多智能体框架，最终与 CAMEL（U20）合成三框架对比表，回答「同一个多智能体任务，不同框架怎么建模」。AutoGen 特点是**角色即 Agent（RoundRobin 轮转）+ 终止条件 + 用户代理**。

## 怎么验证的

- 四角色完整协作跑通（exit 0），消息序列 PM→Engineer→CodeReviewer→UserProxy(TERMINATE) 齐全；
- 生成代码执行验证：`distance((0,0),(3,4)) = 5.0` ✅（期望 5.0，math.hypot 实现正确）；
- 数字来自脚本计时（time.perf_counter）与消息流统计，非估算。

## 踩坑（一手）

1. **stepfun 配额耗尽（402 quota_exceeded）被框架静默化**：run_stream 立即返回 0 消息、表面"正常结束"，实际是底层 API 402、异常被多智能体框架吞掉。→ 切 deepseek 端点解决。**教训：多智能体的失败很难从表面输出看出来，排查要先直接验证底层 API。**
2. **任务文本含终止词 = 团队立即结束**：`TextMentionTermination("TERMINATE")` 扫描所有消息，任务描述里写"回复 TERMINATE"会让 user 消息一发出就满足条件。→ 任务文本避开终止词。
3. **UserProxy 默认交互式**：无头环境无 stdin，轮到 UserProxy 就 `EOF when reading a line` 崩溃。→ 必须给 `input_func` 模拟用户（返回 TERMINATE）。
4. **非标准模型必须显式 model_info**：OpenAIChatCompletionClient 对不在白名单的模型（deepseek-flash）报 `model_info is required`。
