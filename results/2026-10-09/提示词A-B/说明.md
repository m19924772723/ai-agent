# 成果 2026-10-09：提示词 A/B（few-shot 锚点 vs 纯口径）——U13 单元

> 五要素：做了什么 / 为什么 / 怎么验证的 / 关键输出 / 复现步骤

## 做了什么

用 **promptfoo** 对同一任务的**两版提示词**做了一次控制变量 A/B：反馈分类任务（U9 评测集 20 条带真值），v1=纯口径描述，v2=+严重度 few-shot 示例锚点（高/中/低 各 3 条）。A/B 动机直接来自 U9 结论 3（严重度最不稳 17/20、错误方向相反 → 需要锚点验证）。

## 为什么

计划 U13~U14 验收：「对同一提示词的两版做一次 A/B → 产出对比报告（谁赢、差多少、样本量多少）」。同时把 U9 的开放问题（要不要加锚点）变成可复现实验，而不是靠直觉。

## 怎么验证的

| 项 | 证据 |
|---|---|
| 控制变量 | 两版只差锚点一处；模型/温度(0)/数据集/判分逻辑全同 |
| 40 次真实调用 | `--no-cache` 强制重跑，35 s，tokens 34,572（8,145 prompt + 26,427 completion） |
| 判分与 U9 同源 | analyze_ab.py 用 U9 的原始真值逐字段精确匹配（无 LLM judge，避免引入新的判分器） |
| 统计检验 | McNemar 二项精确检验（20 条小样本专用），p=0.375 标注不显著 |
| 无污染 | promptfoo transform 全移除，Python 侧多位置 raw_decode 解析，含 Thinking 前缀容错 |

## 关键输出（实测数字）

| 版本 | 全对 | 类型 | 严重度 | 模块 |
|---|---|---|---|---|
| v1 纯口径版 | 12/20 | 19/20 | **15/20** | 17/20 |
| v2 锚点版 | 15/20 | 19/20 | **19/20** | 17/20 |

- 严重度 **15→19**，全对 **12→15**；类型、模块零变化（说明锚点只影响它教的那一维）
- 5 条不一致：4 条 v2 赢（S08 退款没提示判中、S13/S18/S19）、1 条 v1 赢（S15 优惠券争议）
- McNemar p=0.375 → **方向正面、20 条样本不统计显著**，结论带边界

**踩坑（一手证据，见 README_AB.md）**：① step-3.7-flash 把 `Thinking: ...` 推理文本写进输出 content（提示词塞 user 消息时必现）→ 40/40 transform 失败；② promptfoo v0.124 results.json 是 v3 格式（输出在 response.output）；③ 缓存会带"空输出的假成功"→ 必须 --no-cache。
