# 成果 2026-10-12：工具调用链 + Agent 类型选型发现（U16 单元）

> 五要素：做了什么 / 为什么 / 怎么验证的 / 关键输出 / 复现步骤

## 做了什么

1. 设计强依赖任务（"距 2026-11-01 还有多少小时？除以 7"）：hours_until 的结果 → calculate 的参数，缺一不可。
2. 用 SimpleAgent 跑 4 次、ReActAgent 跑 2 次，从框架 trace 提取调用序列并**自动校验依赖链**（参数是否来自前步结果、顺序、答案）。
3. 发现 **SimpleAgent 收尾失败**（4/4 答"无法回答"）vs **ReActAgent 一次答对**——框架选型决定行为。

## 为什么

计划 U16 验收"工具调用链（2 步以上依赖）"。U15 已证明并行工具调用，U16 要证明**串行依赖**（工具 A 的输出是工具 B 的输入）真发生——这比并行更接近真实 Agent 场景（搜索→提炼→写报告）。

## 怎么验证的

| 项 | 证据 |
|---|---|
| 依赖链真实发生 | trace 提取：hours_until 返回 467.96 → calculate args="467.96 / 7"（±0.5 自动比对 ✓） |
| 顺序正确 | hours_until step1 → calculate step2（step 号比对） |
| 答案与真值一致 | 66.85 = 467.96/7 保留两位（答案含该串 ✓） |
| 可复现 | ReActAgent 重跑 2 次全过；SimpleAgent 4 次全败留档为对照 |
| 对比证据 | 同模型/同温度/同工具/同任务，仅 agent 类型不同 → 结果天差地别 |

## 关键输出（实测）

**ReActAgent（成功）**：回答 14.42 s → "距 2026-11-01 00:00 还有 467.96 小时。467.96 ÷ 7 = 66.85"；校验：链 ✓ 顺序 ✓ 答案 ✓

**SimpleAgent（失败，4 次一致）**：调用链完美（hours_until→467.95→calculate→66.85），但最终回答"抱歉，我无法回答这个问题"——耗时 8.36 / 7.79 / 9.16 / 35.23 s

**trace token 诊断**：SimpleAgent 收尾 step 仅 45 completion token（放弃信号）；ReActAgent 收尾明显更长（会继续推理）

## 两条结论

1. **工具依赖链在框架里真发生且可校验**（自动判据：参数含前步结果 + 顺序 + 答案）。
2. **选框架 = 选行为**：SimpleAgent 是"调用型"（拿了结果就交差，不说出口），ReActAgent 是"推理型"（会收尾成答案）。任务需要哪种行为选哪种。
