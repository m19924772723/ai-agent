## 2. 核心概念（3–5 条，每条一句话，要能回答「所以呢」）

1. **Agent Loop 的"停止原因"比"最终答案"更重要**：把 `None` 换成 `stop_reason ∈ {done, max_steps, budget, loop_guard, model_error}` 之后，"是模型没收尾、工具没返回、还是预算不够"一眼可分——**所以**面试里"失败怎么排查"要讲的就是这套分类，而不是"我调了几次 prompt"。
2. **预算闸必须在发起调用之前**：第一版把预算判断写在收尾之后，等于每次超预算都白花一轮；改成循环开头先查 → **所以**"成本控制"要落在控制流的位置上，不是加个计数器就行。
3. **工具异常要转成可读文本回填，而不是抛出**：`TypeError`（参数对不上）与工具内部异常分开描述，模型才有机会自己改——**所以** U6 那个 `count("keyword")=0 被当真事实` 的坑，从工具侧就能防一半。
4. **"教材跑不起来"多数是 API 契约变了，不是环境坏了**：1.0.0 的 `llm.invoke()` 返回 `LLMResponse`，书里当 str 用 → 两处解包即可；异常类型 `ValidationError(content=LLMResponse)` 已经把答案写脸上了——**所以**排查顺序是"读异常 → 看签名"，而不是重装环境。
5. **可测性是设计出来的**：把模型调用做成可注入的 `model_fn`，11 个用例 0.05 秒跑完、零 token；两条真实用例则花 30 秒约 8k token——**所以**测试分层（离线契约测试 + 少量真机冒烟）是 Agent 项目省钱的关键。

**踩坑一（我自己写的 bug，被测试抓出来）**：`test_budget_exhausted` 首跑失败——`assert ('done' == 'budget')`。
怎么试的：把预算判断的位置从头看一遍，发现它在"模型已收尾"之后才判，等于超预算那次调用已经发出去了。
结果：把预算闸改成**前置**（循环开头 `if total_tokens >= max_tokens: break`），并把用例改成断言 `tokens == 100 and len(steps) == 1`，把这个行为锁进测试。

**踩坑二（教材 vs 框架版本）**：母本 chapter7 的测试在框架 1.0.0 下 `7 passed, 3 errors`。
怎么试的：逐条看异常 → `ValidationError: content Input should be a valid string, input_type=LLMResponse` + `TypeError: expected string or bytes-like object`；再去看 `HelloAgentsLLM.invoke` 签名，确认返回类型是 `LLMResponse`（dataclass，虽有 `__str__`，但 pydantic 校验与 `re` 不走它）。
结果：两处解包补丁 → `7 passed`；另外两个文件（`my_plan_solve_agent` / `my_reflection_agent`）**教材里就没有**，属缺件，不是环境问题。详情见 `labs/ch07-simple-agent/COMPAT-REPORT.md`。
