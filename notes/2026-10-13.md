## 2. 核心概念（5 条，每条能回答「所以呢」）

1. **框架的"内置工具"是四件套而非单一记忆**：Skill（按需加载知识）、Task（子代理隔离）、TodoWrite（任务进度）、DevLog（开发日志）——**所以**"Agent 记忆"在框架里拆成了四个职责不同的工具，用时按需取用。
2. **TodoWrite 是"声明式覆盖"**：每次提交完整列表（不是增量），单线程强制最多 1 个 in_progress——**所以**状态永远可恢复，跨会话续跑靠它（对应第 8 章记忆主题前置）。
3. **DevLog 是"结构化的开发过程记录"**：category+content+metadata+tags，落盘 memory/devlogs/——**所以** Agent 的决策过程可以被审计（延续 U16 的"看 trace 不看答案"纪律）。
4. **Skill 是"渐进式披露"**：不把知识塞进 system prompt，需要时才加载进 tool_result——**所以**长技能库不撑爆上下文，是"上下文工程"的早期形态（第 9 章主题）。
5. **Task 是"上下文隔离"**：子代理独立历史 + 摘要返回，避免污染主上下文——**所以**长任务拆子代理的成本收益：主上下文干净，但子代理要独立花钱。

- TodoWrite 落盘：3 步 pending 清单 + summary + stats（total 3 / pending 3）

- 回答：Success Rate / Task Completion Rate / Efficiency（效果/质量/效率三维）
- 观察：模型对 DevLog 的 category 两次调用用了不同值（development/decision）都被接受——category 校验宽松，但落盘统一归到实际类目

## 4. 能讲给面试官的一段话（3–6 句）

> "我系统摸了一遍 hello-agents 框架的四个内置工具，并实测验证。TodoWrite 是任务进度管理，每次提交完整清单、强制单线程，落盘到 memory/todos——我让 agent 把一个调研任务拆成三步待办，它真的写出了结构化清单。DevLog 是开发日志，category 加内容加标签，落盘 memory/devlogs——agent 记了一条决策日志，说为什么做这个调研，还自动打了 agent/evaluation/metrics 三个标签。
> 还有两个更重要的：Skill 是渐进式披露的知识加载——不把知识塞进 system prompt，需要时才加载，这其实是上下文工程的一种形态；Task 是子代理隔离——子任务用独立上下文跑，返回摘要，避免主上下文被撑爆。
> 这给我的理解是：框架里没有单一的'记忆'，而是四个职责分明的工具，选型要看任务要哪种行为——要跨会话续跑用 TodoWrite，要审计决策用 DevLog，要领域知识用 Skill，要隔离子任务用 Task。"
