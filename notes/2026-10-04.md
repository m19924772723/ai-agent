## 2. 核心概念（3–5 条，每条一句话，要能回答「所以呢」）

1. **框架替我们干的第一件事是"工具契约"这一层**：我只注册两个工具函数，框架自己把 schema 喂模型、解析 `tool_calls`、执行、回填，并且在**一步里并行跑了 2 个调用**——**所以** "什么时候手写循环、什么时候用框架"的判据是：要不要自己承担协议层的坑（U5 那三个坑）。
2. **框架是"有状态"的，状态默认写在当前目录**：它自动创建 `memory/{sessions,todos,devlogs,traces}`、`skills/`、`tool-output/`，并落 jsonl+html 轨迹——**所以** 用框架 = 接受它的目录约定，同时白拿一套轻量可观测性（等价 Langfuse 的入门功能）。
3. **框架会自动注册内置工具**：本次 6 个工具里有 4 个（Skill / Task / TodoWrite / DevLog）是它自己加的，首轮 prompt 就 1523 token——**所以** 上下文预算里"工具 schema"是一项真成本，要主动裁剪（`agent.list_tools()` 先看清单）。
4. **1.0.0 的工具契约走原生 tool calling，不再往 system prompt 里拼工具说明**（`_get_enhanced_system_prompt()` 返回原句）——**所以** 网上的老教程（拼接提示词那套）在此版本上会对不上，这也是 U3 结论的版本级印证（书里钉的 0.2.3 与 1.0.0 有差异，属正常演进）。
5. **四个范式在框架里是并列的类**（`SimpleAgent / ReActAgent / PlanSolveAgent / ReflectionAgent` 都直接继承 `Agent(ABC)`）——**所以** 换范式 = 换类，工具层和 LLM 层不用重写，这也解释了框架为什么能同时提供四种范式。

```

🧮 正在计算: (123+456)*7/3 → 1351.0
回答（7.02 s）：1. (123+456)*7/3 = 1351.00  2. '你好 hello' 共有 8 个字符
```

框架 trace（`memory/traces/*.jsonl`）：

| 步 | tool_calls | usage（prompt / completion / total） |
|---|---|---|
| 1 | **2 个并行**：`python_calculator("(123+456)*7/3")` + `word_count("你好 hello")` | 1523 / 130 / 1653 |
| 2 | 0（收尾） | 1619 / 122 / 1741 |
| 合计 | 2 步 | **3394 token** / 7.02 s / success |

**踩坑**：我脚本里的期望值手写成「'你好 hello' = 7 个字符」，模型答 8。
怎么试的：对着 trace 里 `word_count` 的返回 `'你好 hello' 共 8 个字符` 数了一遍——你/好/空格/h/e/l/l/o = 8。
结果：**模型对、我的判据错**。已把期望值改成 `len("你好 hello")` 由代码算。教训一句话：**判分脚本本身也要可验证，期望值不能手写**（和 U4"数字必须来自真实输出"是同一件事的另一面）。

**顺带关掉 U3 遗留项**：该端点**支持并行 tool_calls**（框架 trace step1 显示 2 个调用同一步返回）。
