## 2. 核心概念（5条，每条能回答「所以呢」）

1. **可观测性 = 采集 + 存储 + 渲染三件事，与「用哪个面板」解耦**。Langfuse 只是其中一个存储/渲染端；同一份数据也落成本地 JSONL + 自渲染 HTML 面板——换端（本地/云）时采集器不用重写。
2. **一次调用的原始事实：输入、输出、延迟、token、finish_reason**。成本 = token × 单价，**单价必须来自真实价目表**——没查到 stepfun 正式单价就显示「未定价」，绝不编数字。
3. **观测面板的价值在「回看」和「对比」**：点一行展开完整输入/输出，才能回答「这次为什么错」；异常帧（finish_reason≠stop）红色高亮。关键排版：明细可展开 + 异常可区分。
4. **云版接入要「就绪但可关」**：LANGFUSE_PUBLIC_KEY/SECRET_KEY 配了就发云 trace，没配只落本地——不因云服务不可用而阻塞采集主流程。云端开关是环境变量而不是代码分支。
5. **lab 看得见 → 才谈调优**：U9 评测解决「好不好」，本单元解决「每步发生了什么」，合起来才是迭代闭环。

**6 次调用实测（step-3.7-flash，stepfun 端点，2026-10-08 10:57–10:58）：**

| ID | 耗时 | token | finish | 输出（结构化分类） |

| C05 | 5177.1 ms | 534 | stop | bug/中/内容（保存失败） |
| C06 | 2712.1 ms | 235 | stop | 需求/低/其他（夜间模式） |

合计：**6 次调用 / 2035 token / 平均 3158.8 ms / 失败 0**；单次延迟 1.86s–5.18s（2.8×）——与 U1 一致：延迟波动是常态，单次数字不算数，要看分布。

**面板功能（panel.html，自包含单文件）**：顶部 KPI 卡（调用数/总token/平均耗时/失败/模型/成本口径），表格逐行 ID/时间/输入摘要/输出摘要/耗时/Tokens(P/C)/成本/finish_reason，**点行展开完整输入输出**，异常帧红色高亮。

**Langfuse 云版接入（就绪待 key）**：`collect.py` 检测 LANGFUSE_PUBLIC_KEY/SECRET_KEY/HOST，配齐即发 trace（input/output/usage/latency 全带），没配只落本地并打印「未配 LANGFUSE_*，仅本地采集」。

**踩坑 1（环境）**：bash 下所有 /usr/bin 工具（ls/sleep/mkdir）报 `Device or resource busy`——MSYS 二进制被瞬时锁定（疑似杀软/索引扫描 D 盘），cmd 正常。绕法：python 直改文件 + cmd 直查目录，等锁释放再跑 git。

**踩坑 2（设计）**：首版「前 2 条调用就试发 Langfuse」——没配 key 时初始化客户端会打 Authentication error 噪音。修正：**只有 key 配齐才初始化**。教训：云资源开关用「凭据是否完整」判断，而不是猜用户想用。
