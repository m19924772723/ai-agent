## 2. 核心概念（3–5 条，每条一句话，要能回答「所以呢」）

1. **消息驱动架构**：AgentScope 把所有智能体交互抽象为 Msg 消息（name/role/content/metadata），而不是函数调用 → 「所以呢」：点对点/广播/组播路由、跨进程 RPC、持久化都是消息层的职责，智能体互不感知位置。
2. **MsgHub 消息中心**：async with MsgHub(participants, enable_auto_broadcast=True) 动态建私密频道（狼人夜聊）、fanout_pipeline 并发收集决策（投票）、sequential_pipeline 顺序发言 → 「所以呢」：多智能体场景（狼人协商、并发投票）用组合组件拼，逻辑与状态解耦。
3. **结构化输出 = 规则约束**：每个动作绑定一个 Pydantic 模型（VoteModelCN、WitchActionModelCN），模型通过 finish function 工具调用返回参数，框架 model_validate(kwargs) 后存入 msg.metadata → 「所以呢」：游戏规则（投票目标必须存活、女巫解药毒药互斥）从「提示词求它遵守」变成「代码强制校验」。
4. **ReActAgent 收尾靠 finish function**：generate_response 是内置收尾工具，结构化模型通过 toolkit.set_extended_model(finish_function_name, model) 注入 → 「所以呢」：JSON 解析失败时调试先看这个工具的参数 schema 和 _react_agent.py 的 _arg_parsing。
5. **生命周期**：AgentBase 统一初始化/运行/暂停/销毁，开发者只需实现 reply()；本 demo 分层：游戏控制层（ThreeKingdomsWerewolfGame）→ 交互层（MsgHub）→ 角色建模层（ReActAgent + 双重身份提示词）。

**踩坑**（面试官问「失败怎么排查」时讲这段）：

1. **mcp 版本冲突**：agentscope==1.0.2 要求 mcp>=1.13，但 uv 默认装 mcp 2.3.0 → ImportError: cannot import name 'streamablehttp_client'（2.x 改名 streamable_http_client）。解法：钉 mcp>=1.13,<2 → 1.30.0。
2. **缺 tqdm**：agentscope 的 evaluate 模块 import tqdm 失败（ModuleNotFoundError）→ 补装。
3. **OpenAIChatModel 的 __call__ 收 list[dict] 不是 Msg**：直接调用报 TypeError，框架内部会先过 formatter → 探针要按框架用法写。
4. **stepfun 配额 402**：quota_exceeded，改走官方 deepseek。
5. **deepseek-flash 是推理模型，多轮必报 400**：The reasoning_content in the thinking mode must be passed back to the API，因为 AgentScope 的 OpenAI formatter 丢弃 thinking 块不回传 → 解法：generate_kwargs={"extra_body": {"thinking": {"type": "disabled"}}} 关思考模式（实测 2.47s 且不再 400）。
6. **Error in block input ['response'] 噪音**（14 次/局）：_react_agent.py:49 的调试 print，finish function 参数里没有 response 字段（纯结构化模型）时 .get("response") 落空 → 只是显示层瑕疵，metadata 结构化数据照常写入，游戏逻辑不受影响。
7. **我自己的补丁 bug**：第一版在 main 里先 setup_game(4) 再 run_game()，而 run_game 内部又 setup_game() → 出现「4 人后又 setup 出 6 人，共 10 名玩家」的重复玩家。修：把人数收敛到 run_game 内部一处。

## 4. 能讲给面试官的一段话（3–6 句，含取舍与数字）

> AgentScope 是工程化优先的多智能体框架（阿里达摩院），核心是消息驱动：所有交互走 Msg，MsgHub 管路由、fanout_pipeline 做并发收集。我把教材的「三国狼人杀」demo 从 DashScope 适配到 OpenAI 兼容端点（deepseek-flash + thinking 关闭），4 人 1 轮跑了 10 次 LLM 调用、10129 输入 + 1797 输出 token、LLM 46.6 秒跑完整局，查验和投票判定全对。最大的体会是它的结构化输出把「游戏规则」变成代码约束——投票目标必须是存活玩家（Pydantic Literal 枚举）、女巫解药毒药互斥，模型不遵守会被 model_validate 校验拦下返回重试，而不是靠提示词求它。代价是框架偏重（venv 156 MB，且消息驱动/异步范式对简单场景是过度设计），这也是它和 AutoGen（对话驱动）最根本的路线差异。
